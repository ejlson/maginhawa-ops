Let finance change the EOD report themselves

A report builder in head office. Finance write sums the way they would in Excel, using names instead of cells. The app draws the flowchart from those sums, tests every change against a known day, and nothing can be published while a test fails. Try it below: add an input, rename it, drag its dot onto a calculation, or ask the assistant for a change.

Making it easy to follow

Version 3 of this design
1Read left to right, in four labelled columnsInputs → Calculations → Day totals → Checks & actions. Boxes arrange themselves, so lines rarely cross and nobody has to tidy up. You can still drag a box, and Tidy up puts it back. As in Make and Dify.
2Click a figure to follow itEverything that feeds it, and everything it feeds, stays bold; the rest fades. Like Excel's Trace Precedents and Trace Dependents.
3Plain English first, formula when you need itEach box says what it means ("What lunch made after service charge, VAT and discounts"). The formula appears when you open the box.
4Every formula shows its working£1,200.00 − £120.00 − £180.00 − £50.00 = £850.00, using the test day. Mistakes show up straight away. n8n shows real data on each step in the same way.
5Type [ to pick a figureSuggestions as you type, so nobody has to remember exact names. Like the formula editors in Notion and Airtable.
6Map or ListThe same report as a spreadsheet-style list, for anyone who prefers rows to boxes. On a phone, List is the better view. Causal offers both.
7Colour says what a box isIndigo is an input, slate is a setting, purple is a calculation, teal is a check or action. The same colours appear on the formula chips, the lines and the column backgrounds, so you can read a formula's source at a glance. Green, amber and red still only mean good, watch and wrong.
8Lines that move and carry valuesWhen you follow a figure, dots flow along its lines in the direction the money moves, and each line shows the amount it carries (£850.00 into Day total net). Movement shows direction better than arrowheads. It stops if the device asks for reduced motion.
9A clear path to liveThe hero card shows four steps: Change made → Tests pass → Published → Live. Seeing how far along you are keeps people going (the goal-gradient effect), and a test that turns green gets a small pop.
·LaterZoom and a mini-map, search to jump to a figure, a comment on any box, and undo for each step

Why not a pure flowchart?

A flowchart is the right picture for what happens after submit: checks, emails, alerts, approvals. That's the third tab, and it works like Power Automate.

It is the wrong tool for writing sums. In Power Automate, "gross minus VAT" becomes a box per step plus expressions like sub(…). Finance already think in named figures, the way Causal works. So they type [Lunch gross] − [Lunch VAT], and the canvas draws the lines for them.

What finance can change without us

+Add, rename, reorder or hide fieldsA new till figure, a required toggle, help text
+Write or change calculationsNet, percentages, fees, targets, using names and + − × ÷ ( ) > <
+Change settings and thresholdsFloat, wage lines, platform shares, per site
+Change what happens after submitWho gets the email, which figures it shows, alerts
—Still ours: new step types, new data sourcesA new integration or step type is a code change, then it appears in their list

How it fits what we've built

The report
Becomes a definition: fields, formulas, settings and after-submit steps as versioned JSON in a new SharePoint list, ReportDefinitions.
packages/core
Gains a safe formula reader (no eval). Today's rules become definition v1.3. The current Vitest tests stay, and every test day runs in CI too.
eod-web
Draws the EOD sections from the definition. A new head-office page, Report builder, for the finance role only.
submit-eod
Loads the version the report was started on, re-runs it, and saves DefinitionVersion with the official figures. Past reports never change.
Assistant
Goes through the planned Netlify AI proxy (Claude). It returns a proposed change list, never a published version.

Safety rails

Tests must pass to publishChanging an expected figure is allowed, but it is listed as a change and needs a reason
Publish when readyNo second person needed. Tests must pass, and it starts on the next trading day
Starts on a set trading dayNever mid-shift. A report started on v1.3 finishes on v1.3
One-click roll backTo any earlier version
Locked basicsCash difference and required-section blocks stay on, so tips and cash rules can't be removed by accident
